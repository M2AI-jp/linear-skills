# Hookの責任

利用側の既存入口から指定Project・原要求・正本・許可済み範囲を受け取り、導入済みlinearの共通運用契約と担当Issueの対象版・依存・受入を確認する。このリポジトリ自体の開発時だけ、ルートの開発入口と正本を使う。配布先へ本開発のSSOTやProjectを要求しない。

- `linear_read.py`: 既存APIから現行データを読む。書込・認証情報の複製・業務台帳を持たない。
- `linear_delete.py`: 現行入口と一致したProjectだけを固定mutationで削除し、同じIDの削除状態を読む。汎用書込APIを公開しない。
- `github_read.py`: 既存ghの認証でPR・保護・必須チェック・mainを読み、対象版を照合する。チェックの意味はPMへ返す。
- `runtime.py`: Codexイベントを受け、対象・状態・依存・読戻しを検査する。業務の意味の真偽は機械認定しない。
- `test_runtime.py`（ソースツリーの局所試験）: 原要求の拒否条件と正常・訂正経路を試す。実装の文言一致を合格にしない。配布先の実行依存には含めない。
通常経路の受入は、正規UIで信頼したCLI／Desktopで実イベントと副作用を観測する。開始・不正操作拒否・許可済み正常操作・読戻し・終了を照合し、不発・sandbox由来の拒否をHook成功にしない。

API形式変更は判定・読戻し試験へ、判定変更は拒否と正常系へ、設定変更は信頼・起動・導入確認へ返す。具体的な実行方法と限界は[README.md](README.md)。未知の経路を一律に実証済みへ拡張しない。
