# Linear

ユーザー指示・利用側のAGENTS・現在の所有Issueにスキル適用OFFがあれば、その担当には適用しない。自分の開発・監査で適用状態を先に確定する入口では、通常のLinear読取を先に行う。発見可能であることやHookの案内だけでONへ切り替えない。

利用側の既存入口とユーザー指示から、対象Projectまたは新規作成の意図、原要求・正本、今回の責任範囲・既存の許可を受け取り、[共通運用契約](references/contract.md)を参照して呼出先へ渡す。既知の対象・許可は再質問せず、不明な業務判断だけを確認する。指定範囲外のProjectを無断で探索・混入しない。明示された比較対象や必要な依存先は、各Projectの責任と正本を区別して参照する。

- 新規計画の構築・既存実態の整理 → [linear-refresh](../linear-refresh/SKILL.md)を呼ぶ。
- 現在の計画から実行・訂正・再開 → [linear-pm](../linear-pm/SKILL.md)を呼ぶ。
- 計画の構築・再整理から実行まで求められた場合 → [linear-refresh](../linear-refresh/SKILL.md)の出力を[linear-pm](../linear-pm/SKILL.md)へ渡す。

呼出先が利用可能か確認し、未導入なら接続不足を明示する。状態規則は共通契約に従う。

Linearに関わる通常の依頼と利用側の既存文脈から、Codex自身が必要なスキルと順序を選んで手順を読み実施する。対象が分かればスキル名の指定を求めない。読取依頼は必要な対象を読んで回答し、Refresh／PMの実行工程を追加しない。選択・読込・実施・完了評価を区別し、実ツール結果と元の依頼を引き継ぐ。継続・圧縮後は現在の原要求とProjectを確認し、過去の選択や自動生成の訂正文を新しい業務要求にしない。Hookが未設定・無効・失敗でも、スキル本体の読取・実行・修復は継続できる。

完了は、対象・原要求・今回の責任と既存許可を適切な呼出先へ渡し、依頼の範囲に対応する呼出先の結果を利用者へ返せたこと。選択や読込だけで後続成果を達成扱いにせず、部分達成・評価不能も共通契約に従って引き継ぐ。
