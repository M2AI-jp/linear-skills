# linear-workflow

Linearで追跡している仕事を、計画から実行・確認・引継ぎまで進めるスキル。コードもコード以外（調査、資料、設定、外部サービスの操作、人への連絡）も扱う。

[skills/linear-workflow/SKILL.md](skills/linear-workflow/SKILL.md) の1ファイル。これだけ。

## 導入

1. `skills/linear-workflow/` を、導入先の `.agents/skills/`（Codex）または `.claude/skills/`（Claude Code）へフォルダごと置く
2. 導入先リポジトリ直下の `AGENTS.md`（または `CLAUDE.md`）に、対象のLinear ProjectのURL、毎回読む正本、触ってよい範囲と確認が必要な操作を書く。これがないと次のセッションは対象を特定できない
3. 指定Projectの読取だけで接続を確かめる

このリポジトリの `AGENTS.md` と `DESIGN.md` は導入先へコピーしない。開発の記録で、スキルの動作には不要。

外すときは置いたフォルダを消す。

## いまは導入されていない

`skills/` はClaude CodeもCodexもスキルを探さない場所なので、ここに置いてあるだけでは何も起動しない。`~/.codex/skills/` と `~/.claude/skills/` にリンクはない。

## 確かめたこと・確かめていないこと

確かめたこと。

- 配布物の構造（1ファイル、frontmatterの形、相対リンクの解決）。CIが検査している
- **スキル名を言われなくても選ばれ、`linear` の別の意味では選ばれない。** Claude Codeで非対話セッション8件（sonnetとopus）。`MAT-123`、linear.appのURL、`AGENTS.md` に対象ProjectのURLがある状態での「再開したい」で選ばれ、線形回帰・linear search・無関係な作業では選ばれなかった。Codexでは、スキルを置いた場合だけ本文固有の規則に従った（置かない対照は、本文が禁じている「現状維持」を答えた）
- **導入先のパス。** Codexは `.agents/skills/`、Claude Codeは `.claude/skills/`。どちらも実際に読み込まれた
- **引き継ぎ。** 使い捨ての小さな案件で、1本目が計画をLinearに書いて実装し途中で止め、**冷たい別セッションに `続きやって` だけを渡した。** 2本目はLinearから現在地を復元し、前の報告を信じずに実データで再検証して同じ結果を再現し、終わった仕事をやり直さず、権限で塞いだ経路を迂回もしなかった
- **一文で進むこと。** 「Linearに従ってサブエージェントを好きなだけ呼び出して完成させてください」の1行だけで、計画をLinearに書き、実装し、テストを通し、commitし、確かめた／確かめていないを分けて報告した。4本中1本はサブエージェントに独立検証（答えを渡さず、自分で壊しに行かせる）を任せ、その報告で修正が入った
- 出てきた成果物は観測者が自分で実行して、報告どおりだった（数値は手計算と一致、テストは通る、不正行は行番号つき）
- **Issue層の一巡。** Project＋モジュール単位のMilestone＋Blocked byを張ったIssue 5本、独立した3形式の実装にサブエージェント3本を並行起動、**サブエージェントの報告しかない仕事はDoneにせずIn Reviewで止め**、次のセッションが自分で確かめてからDoneにし、Projectの完成条件を実物で確認してからProjectを完了にした。テスト24件と実データ出力を観測者が検算

- **汚染に気づくか。** 5セッションの連鎖で、4IssueがDoneになったあと**Linearに一切触らず**、別人名義のcommitで時給を1800→1700に変え、**テストの期待値も同じcommitで書き換えて全部緑にした**。食い違いは記録との間にしか無い状態。独立した冷たい2本が両方とも捕まえた。片方の一文: 「テストは9件成功します。ただし、テストを同じ変更で書き換えているため、通っても1800円の仕様を守れている証拠にはなりません」。Linearへの書き込みは0件で、支払額に関わるので自分では決めず、二択と帰結を出して止まった

- **積み上がった記録から現在地を取り戻せるか。** Issue 12本・コメント15件・Project本文に剥がし忘れた「現在地」3層・「完了とみなせる」と嘘をつくProject update・成立しないBlocked by を作り、**食い違いを11件仕込んで答えはどこにも書かず**、`続きやって` だけを渡した。7件を見つけて直し、2件は「残した」と申告、2件を見落とした。**既存テストが誤った挙動を期待値にしていたことまで見抜いて、テストを反転させコードを正本に合わせた**

**規模を上げると、後から直す網羅率は落ちる（測定済み）。** Issue 55本・コメント97件の規模で、同じ3項目が毎回落ちた — Doneの所在が旧入口名、Doneの完了条件がコードと矛盾、Canceledに要求の移動先が無い。**後から直す方向の指示は5通り試して5通りとも0/3。**

**発生源を潰して解決した。** セッション自身に記録を書かせると、所在を**パスで書いてcommitを書かない**（0/5）。パスは改名で嘘になる。置き場所の表を「ブランチとcommitで書く。ファイルパスだけで書かない」に締めたら **4/6**（終わった4件すべて）、改名後の到達率は **commit基準 8/8 対 パス基準 1/4**。残り2件も、セッション自身が書いた記録では成立した — 壊れた現実は冷たいセッションが「Doneだが成り立っていなかった」と検出して直し、中止は理由と要求の移し先の両方が書かれた。**落ちていた3件は、本文が既に禁じていることを観測者が手で書いた産物だった。**

**ただしこの古さは伝播しない（測定済み）。** Doneの本文が「入口は `bin/payroll`」「`NNmin` は受けない」と嘘をついたままの状態で動かし方を聞いた3本は、**3本とも実物から答えた**（`./bin/payroll-digest`、`90min` も通る）。嘘をなぞったものはゼロ。人が読むと誤解する記録の汚れであって、次のセッションが古い結論を正しいものとして扱う失敗ではない。

**残っているのは2つだけで、どちらも機能の欠落ではない。** この版が効いていない時期に書かれた記録（所在がパスだけ、中止に移動先なし）を後のセッションが遡って掃除しないこと（**伝播しないことは測った**）と、読み切る時間が量に比例して伸びること（12本で約3分、55本で約40分）。**再開の正しさは、12本でも55本でも、記録が嘘をついている状態でも落ちなかった。**

一度「『完成させて』と言われたセッションは `AGENTS.md` を書かない」を弱点として書いたが、取り違えだった。書かなかった4本は全部Issue上限で記録を塞がれていて、上限を開けると2本とも書いた。経緯は [DESIGN.md](DESIGN.md)。
