# linear-workflow

リポジトリの仕事を Linear で進めるためのメタハーネス。1文の意図から、そのリポジトリ専用のハーネス（入口・受入・フック・統合の門）を建てる。建てたあとは、入口と機構が進行を運ぶ。

配布物は2つ。

- [skills/linear-workflow/SKILL.md](skills/linear-workflow/SKILL.md): 建てる・引き直すの手順。判断が要るところ
- `skills/linear-workflow/harness`: 導出と門。Python 3 の標準ライブラリだけで動く。モデルを呼ばず、Linearには書かない

設計と経緯は [DESIGN.md](DESIGN.md)。

## 導入

1. `skills/linear-workflow/` を、導入先リポジトリの `.claude/skills/linear-workflow/`（Claude Code）か `.agents/skills/linear-workflow/`（Codex）へフォルダごと置いて commit する
2. そのリポジトリで「Linearで進められるようにして」と頼む。エージェントが Project・Milestone・Issue・受入を作り、`AGENTS.md` に入口を書き、`harness setup` でフックとCIを登録する
3. `harness check --wellformed` が「整っている」と出れば、建て終わり

`harness` がLinearを読む手段は2つ。入口の「Linearの叩き方」に書いたコマンド（GraphQLのJSONを標準入力で受けて、応答のJSONを返すもの）か、環境変数 `LINEAR_API_KEY`。

Codexは、人がそのリポジトリを信頼し、フックを確認するまで、フックを走らせない（初回だけ）。信頼されていないリポジトリのフックは、読まれもしない。

Codexのサンドボックスの中からは、`.codex` に書けない。既定では `.git` にも書けない。だから Codex で建てるときは、`harness setup` と commit を、人がサンドボックスの外で通す（承認する）必要がある。`harness setup` は書けなかったファイルを言い、建て終わりの判定は、スキルを置いた側のフックが登録されるまで通らない。

このリポジトリの `AGENTS.md`、`DESIGN.md`、`accept/`、`tests/` は導入先へコピーしない。

外すときは、置いたフォルダ、`AGENTS.md` の `## 進め方`、`.claude/settings.json` と `.codex/hooks.json` にある `harness` の登録、`.github/workflows/accept.yml` を消す。

## 建てたあとに起きること

| いつ | 何が起きるか |
|---|---|
| 建てた直後 | 前線は、受入を見直すIssue。自動の受入を持つIssueは全部それを待つので、次に入るセッションは、実装より先に受入を攻める |
| セッションを開始する | main の受入結果とLinearから導出した現在地が、文脈に入る |
| 止まろうとする | このセッションで生じたLinearと現実の食い違いが残っていれば、名指しされて止まれない。同じ理由で止められるのは2回まで |
| main に入れようとする | 緑だった受入が赤になる・消える変更は、CIが通さない |

現在地は、たとえばこう出る。

```
現在地（導出 main@4ad8908）
受入  緑 12 ／ 赤 1 ／ 未実装 3
前線  MAT-530 予約の一覧（In Progress、ブランチ mat-530-list（main より 3 先））
      MAT-531 予約の取消（Todo）
待ち  MAT-533 月次の集計（MAT-530 待ち）
食い違い
  MAT-512 今日の予約4件が一覧に出る … Done なのに受入が落ちている
  MAT-498 受入が、Issueに書いた版（3f2a1c9）から変わった: accept/MAT-498_fee
確認が要る  本番の設定変更、送信
```

## ほかの開発に干渉しない

- フックはリポジトリ単位で登録する。語では発火しない
- `AGENTS.md` に `## 進め方` が無いリポジトリでは、`harness` は何も出さずに終わる
- このリポジトリの `skills/` は、Claude Code も Codex もスキルを探さない場所。`~/.claude/skills/` と `~/.codex/skills/` には置いていない。このリポジトリ自身は、機構だけを自分に適用している

前の版（3スキル＋182行の共通契約＋Hook）は 2026-09-23 に配布され、2026-10-14 に他の開発への干渉を理由に撤去された。

## 確かめたこと

合否が状態で決まるものだけを書く。

- **機構。** 書き換えた受入、Done なのに赤い受入、到達できない所在、状態の食い違い、作業ツリーでの受入の変更を仕込むと、`harness` が名指しする。停止の門は新しい食い違いで止め、同じ理由の3回目は通す。統合の門は、緑から赤への変更を拒む。入口が無ければ何も出さない。`python3 -m unittest tests/test_harness.py`
- **このリポジトリ自身。** `harness check --wellformed` が「整っている」を返す。新しいセッションを起動すると、登録したフック経由で現在地が渡る（Claude Code）
- **0から建てる。** スキルのフォルダだけを置いた空のリポジトリで、1文の意図を渡された別文脈のセッションが、約3分で Project・Milestone・Issue・受入（全部赤、実数つき）・入口・フックを作った。観測者の `harness check --wellformed` が「整っている」を返した。依頼を変えて5回
- **1文で完成まで。** 建てたリポジトリで「Linearに従ってサブエージェントを好きなだけ呼び出して完成させてください」だけを渡した。終わったあと、追跡ファイルだけの場所で走らせた受入は全部緑、食い違いは「なし」、開いているのは人が確かめるIssue 1本だけ。4回
  - 1組目は、1本目が commit もLinearの更新もせずに止まった（停止の門が、commit されていない変更を見ていなかった。直した）。冷たい2本目が同じ1文だけで、残っていた実装を Issue ID つきで commit して閉じた。建てるときに紛れた受入の期待値の誤りは、自分では直さず、基準と受入だけを渡したサブエージェントに判定させてから直した
  - 2組目は、**停止の門がセッションを2回止めた**（「受入が main で緑なのに Todo」）。セッションはそのつどLinearを直し、3回目に食い違いなしで通った
  - 3組目は、いまの形（受入の見直しを、ほかのIssueが待つIssueにする）。セッションは最初に見直しを取り、サブエージェントに受入8本を攻めさせた。**実装より前に、Project本文と食い違う受入2本と、緩い照合1件が直った。** そのあと2モジュールを並列のサブエージェントに実装させた
  - 4組目は、最終版（`899c40a`）。建てたセッションは見直しを開いたまま終えた。次のセッションは最初に見直しを取り、「見本の出力を固定で返すだけで通る」などの抜け道を別データと境界の受入で塞いでから、サブエージェント3本で実装した。受入5本が緑、食い違いなし
- **受入の見直しは、文章では賭けだった。** 建てるの手順に「別の文脈に攻めさせる」と書いていた間、3回のうち実行されたのは1回（1回は省略、1回は自分で見直して済ませた）。Issueにして待たせる形にしてからは、次に入ったセッションが最初にやった。受入を書いたセッションがその見直しを閉じると、停止の門が止める。このリポジトリでも、IssueのIDだけを渡した別のセッションが見直しを取り、抜け道を2つ塞いで閉じた
- **遮断器。** ファイルを commit せずに止まろうとし、直すことも断ったセッションは、2回止められ、同じ理由の3回目で通った。残った変更は次の現在地に出る
- **関係のない依頼では選ばれない。** 入口の無いリポジトリで、`続きやって`、テストの依頼、線形回帰、linear search、READMEの修正の5件とも、スキルは選ばれなかった

**Codex（0.163.0）。** 本体を、台本どおりに答える手元のモデルにつないで走らせた。ログインも実物のモデルも要らず、テストになっている（`tests/test_codex.py`）。

- セッション開始時にモデルへ渡る入力に、現在地・スキルの一覧（`.agents/skills/` から）・入口が入る
- commit されていないファイルを残して終わろうとすると Stop が止め、片づければ通り、片づけなければ3回目で通る
- Codexのサンドボックスの中（`.git` に書けない）でも、`harness` は動く。エージェントが手で走らせる `harness check --wellformed` もここで動く。`/tmp` と `TMPDIR` まで書けなくする設定でも、フックが残した結果を読んで現在地を出し、作業ツリーには何も作らない
- `harness setup` が書いた `.codex/hooks.json` を、Codexは Project のフックとして認識する（`codex app-server` の `hooks/list`）

Codexの実物のモデルでの「建てる」と「1文で完成まで」は走らせていない。このマシンのCodexはログインしていない（`codex login status` が `Not logged in`）。モデルを使う試行は、上のとおり Claude で回した。
